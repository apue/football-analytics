# 分析方法

## 从问题而不是图表开始

每项分析应先写成：

> 研究对象 + 足球行为 + 结果 + 比较基准 + 场景范围

例如：

> 在阵地进攻中，曼城进入进攻三区的方式与联赛平均有什么不同，这些方式随后
> 进入禁区或形成射门的效率如何？

避免使用已经假设结论的问题，例如“为什么曼城的肋部进攻最优秀”。

## 问题阶梯

同一主题依次经历：

1. 描述：发生了什么？
2. 比较：与谁或什么基准不同？
3. 关联：哪些模式与结果同时出现？
4. 解释：有哪些合理机制和替代解释？
5. 预测：模式能否在未见样本上推广？

不要为了使用模型跳过前面的定义、描述和比较。

## 证据阶梯

所有发现应标记为以下层级之一：

1. **数据事实**：源数据直接记录的事件、位置或结果。
2. **指标结果**：依据明确规则计算出的数量或模型输出。
3. **足球解释**：结合比赛知识对指标结果作出的解释。
4. **未验证假设**：需要视频、360、追踪数据或进一步研究的机制判断。

示例：

- 数据事实：某队 62% 的进攻三区进入由传球完成。
- 指标结果：按本项目定义，右侧肋部进入后的禁区触球率高于联赛均值。
- 足球解释：球队可能更擅长从右侧连接中场和边锋。
- 未验证假设：球队主动在左侧吸引压迫后转移到右侧。

## 分析单位

开始计算前明确一行数据代表什么：

- 事件
- 射门
- 控球回合
- 比赛
- 球队比赛
- 球员比赛
- 球员赛季

分母必须与问题一致。总次数、每 90 分钟、每 100 次控球和每次进攻三区进入
回答的是不同问题。

## 比较与语境

至少检查：

- 主客场
- 领先、战平和落后状态
- 对手强度和对手风格
- 球员位置与实际角色
- 样本量和出场时间
- 定位球与开放比赛
- 数据供应商的事件定义

相关性不自动表示因果。复杂模型也不自动比清晰的描述性分析更有价值。

## 事件数据边界

事件数据主要观察球上动作。它通常不能连续观察：

- 整体阵型和防线距离
- 无球跑动和空间占据
- 没有被选择的传球路线
- 持续压迫结构
- 战术指令和球员意图

StatsBomb 360 在部分事件瞬间提供周边球员位置，可以缩小这个缺口，但不等于
连续视频或完整追踪数据。

## 结果审查

每项分析至少回答：

- 数据范围和样本数是什么？
- 定义是什么，是否存在其他合理定义？
- 是否有缺失值、重复事件或方向问题？
- 与简单基线相比如何？
- 改变阈值后结论是否稳定？
- 哪些结论来自数据，哪些来自解释？
- 什么证据可能推翻当前结论？
